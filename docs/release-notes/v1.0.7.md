## 繁體中文

- **知識庫**：自己挑要放進知識庫的文件（「文件 › 📚 知識庫」的「⬆ 上傳到知識庫」，或在專案文件勾選後「加入知識庫」；只有 leader 和管理員能放進、移出）。放進去的 md、txt、docx、pptx（含講者備註）、xlsx 會在背景抽出文字、依標題分段，人和 AI 都搜得到原文；PDF 和圖片只留原檔。含疑似密鑰（Token、私鑰、連線字串密碼）的文件不建索引。一般專案文件跟以前一樣只存原檔，不抽字、搜不到
- **整理 AI 寫知識頁**：在專案 ⚙「📚 知識庫整理 AI」指定一隻 AI，放進知識庫的文件會自動排進整理卡交給它。它把每份文件寫成一頁摘要，散在多份文件的同一件事寫成主題頁，每個重點附出處〔文件名 › 章節〕；文件互相矛盾時發 [需確認] 問 leader。來源文件換版或移出時，知識頁會標「可能過時」。技能庫多了「📚 知識庫整理」範本，裝了寫法比較一致
- **可以只抽字、不整理**：上傳或加入知識庫時取消勾選「讓 AI 整理成知識頁」，文件照樣抽字、搜得到原文，但不排整理卡；之後想整理再按「請 AI 整理」
- **給 AI 的知識庫工具**：MCP 多了 `aigile_kb_search`（搜知識頁與原文）、`aigile_kb_read`（總目錄、讀一頁）、`aigile_doc_read`（分段讀原文，不在知識庫的文件下載原檔）、`aigile_kb_write`（整理 AI 寫知識頁）；`aigile_doc_upload` 可以帶 `kb=true` 放進知識庫
- **說明第 6 章與導覽**：「？ 說明」多了第 6 章「知識庫」，一步步說明第一次怎麼設定。leader 和管理員可以按「▶ 帶我在畫面上走一次」，聚光燈依目前狀態帶你看知識庫分頁、整理 AI 設定、整理技能裝到哪些 AI、上傳、要你處理；導覽只看不改設定；畫面寬 1000 以上才有這個按鈕
- **Codex 叫醒一律走前景**：Codex 視窗開著才會處理工作，群組點名時直接送進那個視窗；視窗關了，工作會留到你下次打開再做，不再在背景另開 `codex exec`。接入檢查也會在 `~/.codex/config.toml` 補上 aigile MCP 工具的核准設定（改前備份，不動其他設定）
- **要你處理只列被問的人**：[需確認] 只進被指定要回覆的人的清單；沒指定就給專案 leader，沒有 leader 給管理員；只問 AI 的不列進人的清單（AI 照樣被叫醒）。按「已處理」或回覆後，清單上馬上消失
- **待命不再互相擠掉**：watcher 和等待腳本分開登記，不會再把對方當成「別的對話在待命」；同一個資料夾重開等待腳本也不再印這句假訊息。別台電腦、別的資料夾開同一隻 AI，照樣會接手

升級：自己 clone 的，`git pull` 後 `docker compose up -d --build`；用映像的，拉新版 `ghcr.io/alansid/aigile-oss` 再重開。**有三個資料庫升級**（`migrations/004_kb_chunks.sql`、`005_kb_pages.sql`、`006_kb_opt_in.sql`，新增知識庫的表和欄位），啟動時自動套用，SQLite 和 PostgreSQL 都一樣，不用手動做。升級後原有的專案文件都不在知識庫裡，要用的請 leader 再加入。AI 那邊重新貼一次「一行啟動」（或照接入文字重新接上），就會換成新的待命腳本和 MCP 工具；用 Codex 的，接好後請讓 Codex 視窗開著。

## English

- **Knowledge base**: you choose which documents go into the knowledge base ("⬆ Upload to knowledge base" under "Documents › 📚 Knowledge base", or tick project documents and add them; only leads and admins can add or remove). md, txt, docx, pptx (with speaker notes) and xlsx files in it have their text extracted in the background and split by heading, so people and AIs can search the original text; PDFs and images are kept as files only. Documents that look like they contain secrets (tokens, private keys, passwords in connection strings) are not indexed. Ordinary project documents are stored as before: no text extraction, not searchable
- **A curator AI writes knowledge pages**: pick an AI as "📚 Knowledge base curator AI" in the project ⚙. Documents added to the knowledge base are queued on curation cards for it. It writes one summary page per document and topic pages for things spread over several documents, citing each point as 〔document › section〕, and asks the lead with [需確認] when documents contradict each other. When a source document gets a new version or is removed, the page is marked as possibly out of date. The skill library has a "📚 Knowledge base curation" template that keeps the pages consistent
- **Text only, no curation**: untick "Let AI write knowledge pages" when uploading or adding. The text is still extracted and searchable, but no curation card is queued; press "Ask AI to curate" later if you change your mind
- **Knowledge base tools for AIs**: the MCP adds `aigile_kb_search` (search pages and original text), `aigile_kb_read` (index, read a page), `aigile_doc_read` (read the original text in sections, or download the file for documents outside the knowledge base) and `aigile_kb_write` (for the curator AI); `aigile_doc_upload` accepts `kb=true` to add to the knowledge base
- **Help chapter 6 and a guided tour**: "? Help" has a new chapter 6, "Knowledge base", with step-by-step first-time setup. Leads and admins can press "▶ Show me on screen" for a spotlight tour that follows the current state: the knowledge base tab, the curator AI setting, which AIs have the curation skill, uploading, and Needs your attention. The tour only shows; it never changes settings; the button appears on screens 1000px wide or more
- **Codex wakes in the foreground only**: Codex processes work while its window is open, and mentions go straight into that window. When the window is closed, work waits until you open it again; no more background `codex exec` rounds. The onboarding check also adds approvals for the aigile MCP tools to `~/.codex/config.toml` (with a backup, other settings untouched)
- **Needs your attention lists each ask only for the people asked**: a [需確認] goes only to the people asked to reply; with nobody named it goes to the project leads, or the admin when there are none; asks for AIs only are not listed for people (the AI is still woken). It disappears as soon as you mark it handled or reply
- **Standby processes no longer push each other out**: the watcher and the wait script register separately and no longer report each other as "another session on standby"; restarting the wait script in the same folder no longer prints that false message. Starting the same AI on another computer or in another folder still takes over

Upgrade: if you cloned it, `git pull`, then `docker compose up -d --build`; if you use the image, pull the new `ghcr.io/alansid/aigile-oss` and restart. **Three database upgrades** (`migrations/004_kb_chunks.sql`, `005_kb_pages.sql`, `006_kb_opt_in.sql`, adding the knowledge base tables and columns) are applied automatically at startup on both SQLite and PostgreSQL; nothing to do by hand. After upgrading, existing project documents are not in the knowledge base; leads add the ones they want. On the AI side, paste the one-line start again (or reconnect with the onboarding text) to switch to the new standby scripts and MCP tools; if you use Codex, keep its window open once it is connected.
