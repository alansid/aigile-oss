## 繁體中文

- **審查者**：專案可以設定「程式交出去前，先給不是作者的人或 AI 看過」。規則由專案自訂：哪些卡要審、要幾位、要不要有人類、審查者要跟作者「不限／不同模型／不同家」。AI 送審時會記下自己用的模型；沒通過不能請人同意 commit。設定在專案 ⚙「審查」，對話框分成三組、用開關切換
- **驗收一次通過**：「已完成」列表可以勾選、全選，按「驗收通過（N）」一次處理；以前由人完成、還沒驗收的舊卡會自動補上驗收，不再一直掛在待驗收
- **看板載入**：卡片很多時，看板優先放未結案的卡（左邊的欄位），剩下的名額才放最近完成的；放不下時上方會有提示、標題寫「顯示 N／共 M 張」。上限預設 200 張，可以用環境變數 `AIGILE_BOARD_LIMIT` 調整
- **側欄**：電腦版左邊選單可以收成只剩圖示的窄條（按 «／»，或按 `[`），會記住開關；專案很多時清單可以自己捲動
- **專案總覽與團隊頁**：重新設計的總覽頁、專案概觀和團隊頁；專案可以加星號、寫簡短說明
- **一個專案多個程式庫**：例如前端、後端各一個，最多 5 個，指定一個主要的。對話框可以拖曳 ⋮⋮ 排順序、單選「主要」；送審時可以指定用哪個程式庫產生比較連結
- **同名成員**：同一個專案內名字不能重複，不同專案可以同名。畫面上同名時名字後面加短代碼；直接打 @名字 又有同名時，會先問你要叫誰（選「兩位都叫」就換成兩個 @）；AI 發文用 @名字 碰到同名會回 `AMBIGUOUS_MENTION` 並附候選人
- **卡片附件**：卡片和人類紀錄卡可以附圖片或檔案，跟著卡片保存（存在「文件 › 卡片附件」），可以看大圖、下載。人類紀錄卡的附件只有人看得到，AI 就算知道檔案網址也打不開
- **commit 與 push 授權分開**：AI 請你同意 commit 時，畫面只給「同意 commit」；同時要 push 時分兩列，而且只把「要 push 的 SHA」當推送目標，不會再把基底 SHA 拿去授權 push
- **說明頁**：文字維持好讀的寬度、示意圖拉寬，右邊多了「本章段落」目錄；新增第 7 章「技能」，技能頁上方有一段可收起的簡短說明
- **其他**：說清楚哪些檔案會過期（只有訊息附件會自動刪，專案文件和知識庫不會）；知識庫可選擇抽 PDF 的文字

升級：自己 clone 的，`git pull` 後 `docker compose up -d --build`；用映像的，拉新版 `ghcr.io/alansid/aigile-oss` 再重開。**有六個資料庫升級**（`migrations/007_card_reviews.sql` 到 `012_card_attachments.sql`：審查紀錄、專案說明與星號、AI 模型、補驗收、同名成員、卡片附件），啟動時自動套用，SQLite 和 PostgreSQL 都一樣，不用手動做。其中 `011` 在 SQLite 會重建成員表（拿掉名字的全站唯一），資料照樣保留，升級前建議先備份。AI 那邊重新貼一次「一行啟動」（或照接入文字重新接上），就會拿到送審等新的 MCP 工具。

## English

- **Reviewers**: a project can require that code is looked at by someone other than the author, a person or an AI, before it ships. Each project sets its own rules: which cards need review, how many reviewers, whether a person must be among them, and how different the reviewer must be (any / different model / different vendor). AIs record the model they used when they ask for review, and a change that has not passed cannot be sent for commit approval. Set it under the project ⚙ "Review"; the dialog has three groups with switches
- **Verify in bulk**: tick cards in the Done list, or select all, then press "Verify (N)". Old cards that people finished but nobody verified are verified automatically instead of waiting forever
- **Board loading**: with many cards, the board shows open cards (the left columns) first and fills the rest with recently finished ones. When some do not fit, a notice appears and the heading says "Showing N of M". The limit is 200 by default; change it with the `AIGILE_BOARD_LIMIT` environment variable
- **Sidebar**: on desktop the left menu can collapse to an icon strip (« / », or press `[`) and remembers the choice; long project lists scroll on their own
- **Project overview and team pages**: redesigned overview, project and team pages; projects can be starred and given a short description
- **Several repositories per project**: for example one for the front end and one for the back end, up to 5, with one marked primary. Drag ⋮⋮ to reorder and pick the primary with a radio button; a review request can name the repository to use for the comparison link
- **Members with the same name**: names must be unique within a project but may repeat across projects. Same-name members get their short code after the name, and typing @name when it is ambiguous asks whom you mean ("both" turns it into two mentions). AIs posting an ambiguous @name get `AMBIGUOUS_MENTION` with the candidates
- **Card attachments**: cards and human-record cards can carry images and files that stay with the card (stored under "Documents › Card attachments"), with a large view and download. Attachments on human-record cards are visible to people only; an AI cannot open them even with the file address
- **Separate commit and push approvals**: when an AI asks you to approve a commit, you only get "Approve commit". When it asks for both, they are on two rows, and only the "SHA to push" counts as the push target, so a base SHA is never offered for push
- **Help**: text keeps a readable width, figures are wider, and a "Sections in this chapter" list sits on the right. A new chapter 7, "Skills", plus a short dismissible note at the top of the skills page
- **Also**: clearer wording about what expires (only message attachments are deleted automatically; project documents and the knowledge base are not), and optional PDF text extraction for the knowledge base

Upgrade: if you cloned it, `git pull`, then `docker compose up -d --build`; if you use the image, pull the new `ghcr.io/alansid/aigile-oss` and restart. **Six database upgrades** (`migrations/007_card_reviews.sql` to `012_card_attachments.sql`: review records, project descriptions and stars, AI models, verification backfill, same-name members, card attachments) are applied automatically at startup on both SQLite and PostgreSQL; nothing to do by hand. On SQLite, `011` rebuilds the members table to drop the site-wide unique name; data is kept, but take a backup first. On the AI side, paste the one-line start again (or reconnect with the onboarding text) to get the new MCP tools such as review requests.
